# 显示与画质

[项目首页](../README.md) ｜ [硬件支持](HARDWARE.md)

默认目标内核按 OS2.0.6.0.VMYCNXM 对齐面板流程，保持 2880 × 1800，首选 120 Hz。
7.3 的多刷新率修正默认提供 90/120/144 Hz；低刷新率仍有闪烁，单独保留诊断开关。
目前真机验证限一台天马屏 liuqin；CSOT 命令和 PHY 参数已离线核对，尚未真机验收。
天马普通熄屏/亮屏已加入首次唤醒顺序修正；早期显示接管、长期使用及其他面板仍需扩大测试。

## 刷新率

默认提供 **90 / 120 / 144 Hz**，首选仍是 120 Hz。切换使用普通 DRM modeset，
会经过关屏、面板初始化与触摸固件加载，可能短暂黑屏；未实现无缝切换、自动刷新率或 VRR。
`panel_novatek_nt36532.liuqin_multi_refresh=0` 可退回单一 120 Hz。
未知面板、缺少双 DSI 刷新率查询接口及旧 6.17 配方保持原有模式。

模式和时钟使用以下约束：

- 使用固定 ROM `msm_drm.ko` 的 **M81 专用 HFP/VFP 表**，并在面板就绪前发送对应的
  B3/B2 扫描命令。原实现仅扩大 VFP，不能代替 M81 的专用时序。
- 所有档位请求完全相同的 DSI 像素/字节时钟。DRM 的整数 kHz 舍入原先会改变 PLL 的
  VCO/分频组合：标称 90 Hz 曾实测约 179.9 Hz，并导致触摸校准失败。
  修正后请求像素时钟 167838626 Hz、字节时钟 125878969 Hz，避免这一切换。

| 标称刷新率 | 全屏 HFP | VFP | DRM 像素时钟 kHz | 默认提供 |
| --- | --- | --- | --- | --- |
| 120 Hz（首选） | 200 | 26 | 785245 | 是 |
| 144 Hz | 52 | 26 | 874197 | 是 |
| 90 Hz | 500 | 26 | 672478 | 是 |
| 60 Hz | 200 | 3148 | 785245 | 否 |
| 50 Hz | 498 | 2524 | 673042 | 否 |
| 48 Hz | 498 | 2758 | 673042 | 否 |
| 30 Hz | 498 | 6270 | 673042 | 否 |

表中 HFP 是完整双路图像宽度；DSC 只压缩有效像素，不能将空白期一起压缩。
两种 M81 面板的 DTBO 和原厂模块常量均已离线核对。测试实际编译执行配方中的面板枚举、
扫描命令及主机时钟函数，见[刷新率测试](../tests/README.md#刷新率模式)。

### 限制

90/120/144 Hz 切换及各档熄屏恢复已验证。60 Hz 仍有闪烁，60/50 Hz 会触发面板告警，低频默认隐藏；CSOT、长期运行、手写笔和系统睡眠仍需补齐测试。

可用 `panel_novatek_nt36532.liuqin_low_refresh=1` 暴露低频，保持 `liuqin_multi_refresh=1`。告警线已为高电平时，没有新中断不能作为异常解除的依据。

## 开关机画面

Fedora 图形启动构建先通过固件帧缓冲显示 Fedora，再交给原生显示驱动。
两段画面共用方向和缩放；原生驱动接手仍需短暂熄屏、复位面板，尚不是连续无黑屏接管。
该改动主要改善等待期间的显示，不保证缩短进入桌面的总时间。

- 开机：在绘制前，根据保留的小米标识别四个方向，本次动画随后保持该方向。
  不启动重力传感器，也不会在动画期间随转动实时旋转；识别失败时回退到横屏。
- 关机：只读监听当前 Wayland 会话的内屏方向，采用退出前最后一次有效值。
  会话或方向不可用时回退到本次开机方向，再不具备时使用横屏。
- 调试：`plymouth.enable=0` 停用动画；缺少固件画面或早期绘制失败时继续原生启动。
  Fastboot 临时启动可能交出黑帧，不能代替普通 A 槽启动的 Logo 对照。

早期画面、方向和缩放已有分项测试；新构建仍须验证普通启动、冷启动与关机。升级应包含根系统中的关机主题、方向服务和插件，不能只更新内核包。

曾捕获根系统的 `plymouth-read-write.service` 等待动画进程约 398 秒，阻塞 `sysinit.target`，
连带推迟网络和登录管理器启动。根系统现在按顺序发送启动与读写切换请求，并限制客户端等待；
超时先记录进程状态，只向核对身份后的 root `plymouthd` 发送退出信号，让后续启动继续。
记录位于 `/run/liuqin-plymouth-guard/events.jsonl` 和对应服务日志，不读取键盘输入或图像内容。
此保护不等于已查明动画进程失去响应的内部原因；已有系统需要更新这些根系统文件才能使用。

## 亮度与 CABC

桌面亮度通过原厂曲线，将 0–4095 的逻辑范围映射到 0–2047 的背光控制值。
最低非零逻辑值 `1` 映射为原厂表中的 `17`，避免 KDE 滑块拉到 0% 时关闭背光；
直接向背光 `brightness` 写入 `0` 仍会关闭背光，关屏与睡眠路径也保留熄灭行为。
CABC 是随画面内容调整的背光策略，不等于色彩校准；实际观感和耗电收益仍需测量。

```sh
liuqin-display-policy status
sudo liuqin-display-policy set ui
sudo liuqin-display-policy set ui --save
```

| 模式 | 原厂策略 |
| --- | --- |
| `off` | 关闭 CABC |
| `ui` | 界面 |
| `still` | 图片 |
| `movie` | 视频 |

不加 `--save` 时只影响本次启动，所选模式会在睡眠唤醒及显示恢复后重新应用。
加 `--save` 写入 `/etc/liuqin/display-policy.json`，由启动服务恢复。
删除该配置并重启即可取消保存的选择；无配置时保留既有初始化策略，不强制开启 CABC。
`programmed` 仅表示命令发送成功，不是硬件寄存器回读，也不保证与 Android 默认策略相同。

## 自动恢复与日志

内核校准保护在一次触摸恢复中最多执行一次显示休眠/唤醒和固件重载，
见[显示与触摸恢复时序](#显示与触摸恢复时序)。它与下述处理面板 GPIO 告警的会话服务独立。

会话恢复服务只在拥有当前活动 Wayland 会话的用户中操作，协调关闭、重新开启显示输出。
它核对面板告警 GPIO 的实际电平，并限制为每用户每 10 分钟最多两次、两次间隔至少 60 秒。
启用 CABC 自适应模式后，PWM 为零可能是正常调光，服务不会仅凭这一项触发恢复。
恢复不重启系统或应用；关屏时不触发恢复，操作前核对活动会话与系统状态。

查看当前用户的恢复记录：

```sh
journalctl --user -b -u liuqin-display-recovery.service
```

查看包含登录界面的记录：

```sh
sudo journalctl -b _SYSTEMD_USER_UNIT=liuqin-display-recovery.service
```

查看初始唤醒、触摸校准及内核恢复记录：

```sh
sudo journalctl -k -b -g 'initial DDIC wake|TDDI|resume failed closed'
```

报告故障时记录出现阶段、是否自行恢复、是否按键或睡眠过。正常重启、拔线冷启动和
登录界面睡眠应分别验收；一次成功启动不能排除偶发问题。

## 已对齐的驱动流程

| 环节 | 当前行为 |
| --- | --- |
| 显示接管 | 先熄背光再接管时钟；修正 MDP/PLL、DSI 频率与 SMMU 交接 |
| 面板初始化 | 按引导选型发送原厂寄存器配置与 PPS，保留包类型、分组、等待和广播拆包；天马初始唤醒命令移至首帧后，未知选型保留原路径 |
| 供电与复位 | 对齐原厂申请顺序与复位波形；关屏保留 IOVDD、偏压，关闭两路 1.3 V；已识别面板省去三处额外准备等待，保留电压及原厂等待 |
| DSI 启停 | 寄存器配置和 PPS 完成后启动视频；关屏按显示控制器停帧、停视频、发送 OFF 的顺序执行；时钟门控保持关闭 |
| PHY | 已知面板、连接关系和链路频率匹配时，使用原厂 D-PHY 时序表 |
| 背光与调光 | 首帧后开启六路 LED，完成天马初始唤醒、正常显示和 CABC，再排队执行额外调光；关屏取消过期任务 |
| 触摸恢复 | 天马显示激活完成后加载固件，稳定校准通过后开放输入；超时最多协调一次恢复 |

为避免睡眠唤醒卡住，正常引导显式设置
`msm.liuqin_oem_clk_gating=0`。完整五路断电、无缝动态刷新率和原生显示状态的无缝继承尚未实现。

### 首次唤醒顺序

天马 M81 曾在普通熄屏后亮屏时持续闪烁、触摸失效，鼠标和系统仍能工作；
触摸固件反复停留在 `0xA1` 校准状态，单次读到 `0xA3` 不能证明已稳定运行。
默认补丁 `0011-liuqin-initial-wake-after-first-frame.patch` 将首次唤醒调整为：

1. 完成原厂寄存器配置及 PPS（显示压缩参数）。
2. 启动视频并完成主机侧首帧；此时面板不必已经显示图像。
3. 发送原 ON 表末尾的 `0x11`（退出休眠，等待 120 ms）与 `0x29`（打开显示，等待 20 ms）。
4. 完成显示激活后加载触摸固件，再检查校准状态并开放输入。

命令报文和原等待值保持不变，每个显示周期只发送一次初始唤醒组，部分传输失败后不重发。
此顺序限于已识别的天马原厂命令表和首帧背光路径；不具备对应回调条件时保留完整 ON 表。
触摸的显示就绪等待独立于自动恢复开关，关闭恢复不会绕过这一依赖。

首帧后唤醒与触摸校准恢复已通过熄屏/亮屏检查。源码执行回归见[显示与触摸初始化](../tests/README.md#显示与触摸初始化)。

### 显示与触摸恢复时序

`0010-liuqin-tddi-calibration-recovery.patch` 保留为异常保护：连续 20 次、间隔 10–11 ms
确认固件达到正常运行状态后才开放输入，最多查询 150 次。仅校准超时允许一次协调恢复：
显示芯片完成休眠/唤醒，再重载一次触摸固件并重新检查；不重启 DPU、DSI 主机或 PHY，
不切换面板复位 GPIO 和电源。失败或关屏取消时保持输入关闭，并向可能仍运行的触摸 MCU 发送深睡命令。

此恢复路径限于对应天马固件的普通恢复，其他面板及手势唤醒不启用这项校准恢复。
校准恢复只能处理失败，不能证明首次初始化正常；验证必须分别记录首次成功和恢复次数。

## 开发对照参数

下列参数用于构建故障对照镜像，不能代替匹配内核、模块与完整回退镜像。
补丁启用顺序由 `build/kernel/source.json` 的 `target_patches` 决定，不按文件编号补全试验补丁。

| 内核参数 | 对照作用 |
| --- | --- |
| `panel_novatek_nt36532.liuqin_multi_refresh=0` | 关闭默认三档支持，退回 120 Hz |
| `panel_novatek_nt36532.liuqin_low_refresh=1` | 额外暴露未通过验收的 30/48/50/60 Hz，仅用于诊断 |
| `panel_novatek_nt36532.liuqin_late_wake=0` | 恢复天马初始 `0x11/0x29` 的原发送位置，用于反向对照 |
| `nt36523_ts.liuqin_tddi_recovery=0` | 关闭稳定校准检查与一次协调恢复；首次显示就绪依赖仍保留 |
| `panel_novatek_nt36532.first_frame_backlight=0` | 停用首帧背光等待 |
| `panel_novatek_nt36532.liuqin_retained_power=0` | 使用旧关屏供电状态，仍保留新的启动供电与触控探测顺序 |
| `panel_novatek_nt36532.oem_batch_commands=0` | 逐条发送开关屏命令 |
| `panel_novatek_nt36532.oem_normal_display=0` | 跳过背光开启后的恢复正常显示命令 |
| `msm.liuqin_oem_dphy_timing=0` | 使用主线计算的 PHY 时序，保留其余面板和背光适配 |
| `ktz8866.oem_brightness_curve=0` | 使用原来的 0–2047 线性亮度接口 |
| `panel_novatek_nt36532.oem_delayed_dimming=0` | 停用首帧之后的额外调光命令 |
| `panel_novatek_nt36532.esd_monitor=0` | 停用 GPIO 告警接口及依赖它的自动恢复服务 |
| `panel_novatek_nt36532.esd_confirm_level=0` | 对照旧告警逻辑，不再核对中断到达时的电平 |
| `msm.liuqin_oem_video_order=0` | 停用原厂开屏阶段排序，项目正常引导设置为 1 |
| `msm.liuqin_oem_shutdown_order=0` | 停用显示控制器停帧后的关屏排序，项目正常引导设置为 1 |
| `msm.liuqin_cmd_dma_schedule=0` | 使用原来的命令发送路径，项目正常引导设置为 1 |
| `panel_novatek_nt36532.liuqin_skip_power_on_wait=0` | 恢复供电后额外的 120 ms 等待，正常引导设置为 1 |
| `panel_novatek_nt36532.liuqin_skip_post_reset_wait=0` | 恢复复位后额外的 120 ms 等待，正常引导设置为 1 |
| `panel_novatek_nt36532.liuqin_skip_post_pps_wait=0` | 恢复 PPS 后额外的 120 ms 等待，正常引导设置为 1 |

### 命令扫描行调度

7.3 默认构建为视频运行中的双路命令设置相同扫描行，并在触发前检查两路行计数。
`msm.liuqin_cmd_dma_schedule=0` 可切回原路径；开关在启动时选择，两个对照可复用内核和模块。

调度等待有上限，传输后恢复原寄存器，部分传输失败不自动重发。命令调度已验证亮屏、唤醒、普通重启和冷启动。边界检查见 [display-cmd-schedule.py](../tests/display-cmd-schedule.py)。

### 点亮等待

原厂 ON 命令表在退出休眠（`0x11`）后等待 120 ms、打开显示（`0x29`）后等待 20 ms，
两处均保留。默认引导省去供电后、复位后和 PPS 发送后三处额外的 120 ms；
原厂复位波形、各路供电稳定时间、命令表和 DSI 调度保持原样。

三个 `liuqin_skip_*_wait` 参数在正常引导中均为 1，分别设为 0 可恢复对应等待。
驱动未收到这些参数、未识别面板身份及其他机型时仍保留原等待。

省去的固定等待合计 360 ms，不等于整机启动能缩短同样时间。天马启动/唤醒已验证，CSOT 与长期表现仍待验证，见[首次唤醒顺序](#首次唤醒顺序)。
