# 待改进与验证

这里保留未完成工作的结论和下一步，不把临时试验或一次成功启动视为正式验收。
完整硬件范围以 [硬件说明](HARDWARE.md) 为准；以下主要来自一台天马屏、8GB / 256GB、HW16.9.0 设备。

## 优先事项

| 项目 | 已知结果 | 下一步与完成条件 |
| --- | --- | --- |
| 偶发开机条纹、闪烁及黑屏 | 普通重启、冷启动均曾复现；关闭再开启输出可恢复，自动恢复也已实测生效。仍不能归因于某一项存储等待或面板改动 | 保存首次故障到恢复的显示状态，核对首次上电与后续重启差异；重复冷启动、重启及登录界面睡眠验收，记录恢复次数 |
| deep 进入与提前唤醒 | 临时诊断内核已通过 RTC 和键盘唤醒短测；长测仍提前结束，同期捕获 ADSP GLINK 和电池通知 `0x80` | 核对通知触发条件与系统级低功耗驻留；CPU 进入 deep 不等于整机达到低功耗 |
| 电量刷新与待机测量 | 容量单位修正已加入构建并临时启动核对；标准计数与两颗电量计可能不同步，也可能同时延迟跳变。五分钟同步对照中容量下降 70 mAh，电流积分约 45 mAh | 核对固件刷新及电量计工作状态，建立覆盖刷新延迟的测量方法；暂不报告准确待机功耗，也不直接替换计数来源 |
| 偶发关机动画卡住 | 曾出现静止画面、输入和网络无响应；与启动显示异常的关系未确定 | 优先保存关机阶段和残留日志，再定位阻塞点；不能只靠再次强制重启判断修复 |

电池通知存在约 **8 分钟活动间隔**的线索：同一启动中的两个通知计数增量跨约 960 秒，
另一轮同一启动中的两次提前唤醒也相隔约 960 秒。中间通知时刻未全部连续捕获，
尚不能确认严格固定周期或排除电量阈值、模型更新；这不是已证明的唤醒根因。

## 本机试验与默认构建的边界

以下内容尚未加入默认构建：

- **键盘仅用 GPIO 50 数据中断唤醒**：曾捕获 GPIO 46 专用中断打断 deep 进入；去掉它后短测与键盘唤醒通过，长测仍提前唤醒。默认内核不能据此标为已完成睡眠修复。
- **唤醒来源及原始电量诊断接口**：用于有限次数的观测，不作为常驻服务；记录和试验源码保留在本机 `out/`。
- **原厂屏幕状态通知**：固件接受 SET 应答，但 GET 不回显状态；长测仍提前唤醒，未设为默认策略。
- **GET 86 周期查询**：五分钟对照未证明能稳定改善容量刷新，未安装默认轮询。直接读取两颗电量计也未证明更及时。

早期独立调光试验已归档，正式调光随设备适配迁移到 7.3。
旧版补丁清单保留在 `source-6.17.json`；当前启用项以默认来源记录的 `target_patches` 为准，不按编号补齐缺项。
设备日志、回退镜像和私有校准留在本机，不随待办文档或源码提交。

## 后续验收

每次候选记录源码与镜像身份、首次画面、是否自动恢复、触控、调光和睡眠唤醒。
固定引导后分别检查普通重启和拔线冷启动；临时启动成功不替代这两项。
修改睡眠路径时还要检查登录界面、桌面、键盘唤醒以及蓝牙串口状态。
128GB / 512GB、CSOT、外屏组合、前摄等覆盖缺口继续保留在硬件说明中，不随本次提交升级为已验证。
