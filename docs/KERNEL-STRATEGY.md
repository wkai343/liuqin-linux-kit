# 内核与更新路线

[项目首页](../README.md) ｜ [构建指南](BUILD.md) ｜ [内核更新](KERNEL-UPDATES.md)

## 当前方案

使用 liuqin 设备内核，保留上游适配并维护板级补丁。
来源、基础提交、配置片段和目标补丁由 `build/kernel/source.json` 记录；
Devbox 构建默认目标时加入键盘、指纹、显示和电池接口适配，安装器内核独立。
当前启用策略及验证缺口见 [待改进与验证](DEVELOPMENT-STATUS.md)。

Fedora 和 Ubuntu 可共用设备内核，通过各自的 RPM/DEB 交付版本化模块与预构建 boot。
不直接换用发行版通用二进制内核：板级适配涉及设备树、显示、DSP、存储、网络、相机等，
不能假设全部改动都能通过几个外置模块补齐。

## boot 与 rootfs 的关系

每组 Image、模块和内核身份必须配套。同一个 kernel release 不应对应不同载荷。
统一根接口允许普通桌面软件和设备服务独立更新；内核包则携带匹配的 boot 和模块。
独立 installer 负责安装传输与存储操作，不随桌面和目标内核的普通配置变化重新编译。

本机原厂 ABL 仍使用 Android 格式的 boot 镜像。仅执行 `dnf update` 或 `apt upgrade`，
不能自动把普通发行版内核变成可在平板启动的镜像。
项目已实现受控引导更新后端，但系统内自动更新尚未真机验收，默认不启用；
在线软件仓库也尚未提供。当前可靠的设备更新方式仍需验证配套镜像与 Fastboot 回退材料。

## 后续方向

| 路线 | 主要工作 | 当前定位 |
| --- | --- | --- |
| 设备内核 + 版本化 RPM/DEB | 维护板级补丁，验证更新与回退 | 当前构建方案 |
| 将适配迁移到受维护的 LTS | 核对已上游化改动，移植剩余补丁，完整硬件回归 | 后续评估，尚未交付 |
| 发行版通用内核 + DTB/外置模块 | 先证明其配置和内部接口满足全部必需设备功能 | 实验路线 |
| U-Boot/UEFI 第二级引导 | 适配显示、存储、启动协议与救援链 | 独立研究，不作为当前前提 |

内核模块 ABI 并不保证跨内核版本稳定，DKMS 也不负责修改内核本身。
通用内核路线需先验证显示、触控、存储、网络、音频、旋转、休眠与恢复；
构建成功或偶尔启动不能替代设备验收。

## 更新边界

内核更新应保留账号、文件、旧模块和可回退的 boot，而不是格式化重装 rootfs。
A 槽启动不代表 B 槽已配置为可用的 Linux 救援系统，当前方案不承诺掉电自动回滚。
包格式、更新步骤、实验开关与回退限制以 [内核更新](KERNEL-UPDATES.md) 为准。
