# FPC1264 OEM TOD

[用户指南](../../../../../../docs/FINGERPRINT.md)记录使用与验收范围。适配器使用锁定的 libfprint 1.95.1+tod1 ABI，通过 `tools/build-tod.sh` 构建，不替换系统 libfprint。

## 录入与引用

fprintd 负责 D-Bus 账号认领、Polkit 授权和手指条目。驱动将目标账号、手指和私有输出路径传给 `native_enrol.py`；提供者复用该账号原有随机凭据与 Gatekeeper handle，在同一个 FPC 会话中完成开始/结束录入的签名授权。

多指使用每账号一份厂商不透明数据库。追加前核对已发布条目，清除已删除或未发布的模板，再验证库存只新增了一个 ID；厂商接口当前按五个槽位处理。数据库持久提交后才返回该手指的独立引用，其他账号及已有条目不改写。发布失败留下的引用不获得认证资格。

FpPrint 使用 RAW `(uay)` 外层格式，版本固定为 2；内容为 `FPCREF2`、Linux UID、手指编号和独立随机令牌。解码器使用同一 ABI 读取私有条目，不枚举设备。

当前组件仅接受此多指格式，不读取或迁移旧单指不透明模板。驱动、客户端、解码器与 Python 助手必须成套升级。

## Verify、Identify 与更新

Verify 请求指定手指，Identify 接收该账号的已录手指列表。驱动保留本次列表，助手核对其与当前已发布条目一致，再对账号数据库进行一次硬件采集/识别。实际匹配 ID 必须映射到本次获准的有效引用；删除、未发布、过期或其他账号的引用不能认证。

自适应数据先在账号锁下持久提交，之后助手只返回本次列表的匹配索引。驱动检查成功退出、清理标记和私有结果格式后，向 libfprint 报告对应 FpPrint；不做主机软件指纹匹配，不把未知 TA 返回码当成功。取消等待原硬件清理结束，提交失败不报告认证成功。

Canonical 数据库以 `gallery.json` 原子替换，保留精确旧文件直至同步完成；中断后仅在账号、完整数据库及已发布引用均可核验时完成提交或恢复缺失的当前文件；损坏或不一致状态阻止后续操作。

## 验证

`tests/fingerprint-gallery.py` 和 `fingerprint-gallery-client.py` 分别检查实际私有文件事务和 C 协议/匹配代码；`fingerprint-abi.py` 在真实 libfprint Enroll/Verify/Identify API 上运行合成进程回归并编译 fprintd。测试不访问传感器或真实模板；物理录入、手指区分与长期恢复另行验收。
